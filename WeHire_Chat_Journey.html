แชทเปิดเฉพาะ “คู่ที่จ้างกันแล้ว” — ล้อตาม Contact Lock เดิม

สิ่งที่ต้องระวัง (สำหรับ SA)

เฉพาะ WeHire — บริบทที่ต้องรู้

1. ขอบเขตแชทผูกกับ “การจ้าง”

1 ห้อง = 1 คู่ที่จ้างกัน (ผูกกับ job_application) · เปิดตอน hired เท่านั้น · เป็น read-only หลัง verified · ไม่ใช่ open DM แบบแอปแชททั่วไป (กันสแปม/คุกคาม)

2. แชท = หลักฐานตอน dispute

เรามีระบบ anti-ghosting + pro-rata settlement · log แชทต้องเก็บ ห้าม hard-delete ตอนมี dispute · admin เข้าถึงได้เฉพาะตอนตัดสิน (+ log ว่าใครเปิดดู)

3. Platform bypass (ความเสี่ยงเชิงธุรกิจ)

คนอาจแลก LINE/เบอร์ในแชทแล้วหนีออกนอกแอป = เสีย matching fee 6% · MVP อย่าเพิ่ง police หนัก (แชทในแอปเสริม stickiness ด้วยซ้ำ) แต่ต้องรู้ว่านี่คือความเสี่ยงเชิงธุรกิจ ไม่ใช่แค่ technical

4. ต่อของเดิม ไม่สร้างใหม่

user_reports · user_blocks · notifications มีอยู่แล้ว → แชทต้องเคารพ block ที่มี + มีปุ่ม “รายงานข้อความ” + ยิง noti เข้าระบบเดิม

ทั่วไป — แต่ผูกกับ stack เรา

Real-time: เราอยู่บน Supabase อยู่แล้ว → ใช้ Supabase Realtime (messages table + subscribe) คุ้มสุด ไม่ต้องตั้ง WebSocket server เอง · MVP จะ polling ก็ได้ (เรา poll notification อยู่แล้ว) แต่ latency สูงกว่า

PDPA (ไทย): ข้อความ = ข้อมูลส่วนบุคคล ต้องมี retention policy + ระบุใน ToS (เรากำลังทำ policy อยู่พอดี เชื่อมกันได้)

Authz ราย row: เช็ค server-side ทุก read/send ว่าคนขอคือ 1 ใน 2 ของห้องนั้นจริง · ห้ามข้อความหลุดข้ามงาน

อย่า over-engineer: 3 tester = จิ๋ว · text-only ก่อน · ยังไม่ต้อง typing indicator / presence / read-receipt · Supabase Realtime free tier เหลือเฟือ
