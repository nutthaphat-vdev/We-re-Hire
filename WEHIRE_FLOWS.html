6. Escrow & Pro-rata Settlement

Phase 3 · ยังไม่ implement (moat หลัก)

Employer จ่ายตามค่าจ้างที่โพสต์ (เช่น 600) · platform หัก 6% จากฝั่ง worker · ปลายทางมี 2 กรณี

กรณี A — Worker ทำครบ (เราได้ 6%)

flowchart TD L[Employer จ่าย 600] --> C[Worker complete ratio 1.0] C --> F[หักค่าบริการ 6% = 36] F --> W["worker รับจริง = 564 (โชว์ให้ worker เห็น)"] F --> P["platform = 36 (6% matching fee)"] W --> B{"564 + 36 = 600 ✓"} P --> B

กรณี B — Worker ไม่ครบ (dispute ratio 0.70 · ไม่เก็บ 6%)

flowchart TD L2[Employer lock 600] --> R[ratio 0.70 ทำไม่ครบ] R --> WG["worker_gross = 600 × 0.70 = 420"] WG --> PN[penalty 10% = 42] WG --> WN[worker รับ = 378] L2 --> ER["employer refund = 180 (เวลาที่ขาด)"] PN --> PF["platform = 42 (penalty · ไม่เก็บ 6%)"] WN --> B2{"378 + 180 + 42 = 600 ✓"} ER --> B2 PF --> B2
  • 6% matching fee: หักจาก worker (employer จ่ายเท่าค่าจ้างที่โพสต์เสมอ) · worker เห็น "ค่าจ้าง 600 − ค่าบริการ 36 = รับจริง 564" โปร่งใส
  • complete → platform ได้ 6% · ไม่ครบ → platform ได้แค่ penalty 10% (ไม่เก็บ 6% เพราะงานไม่ส่งมอบ)
  • ทุก transaction atomic + idempotency key · Decimal ไม่ใช่ float · ratio>1.0 → reject
กรณี A = รายได้หลัก (Stream 1) ที่ทุกงานสำเร็จต้องได้ · กรณี B = สูตร pro-rata เดิมใน CLAUDE.md ถูกอยู่แล้ว
